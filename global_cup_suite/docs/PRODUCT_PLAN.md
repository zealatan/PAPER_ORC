## 0. 한눈에 (Executive Summary)

- **제품 한 줄 정의**: "티커만 넣으면, 전고점 낙폭·배당·재투자·은퇴 인출(FIRE)까지
  과거 데이터로 즉시 백테스트해 보여주는 개인 투자자용 웹 도구."
- **현재 상태**: Streamlit 웹앱(대시보드 + FIRE) 완성. 엔진 검증됨. 로그인·결제·DB 없음.
- **목표**: 정기구독(SaaS) 수익화. 타깃은 **국내 + 해외 둘 다**. 장기적으로 앱스토어 지향.
- **핵심 권고 (본문 §3에서 상술)**:
  1. **웹 SaaS로 먼저 출시**한다. 앱스토어는 검증 후 Phase 3에서.
  2. 그 이유는 (a) Apple/Google이 디지털 구독에 **인앱결제(IAP) 30%를 강제**하고
     단순 웹뷰 래핑을 **심사에서 리젝**하며, (b) Streamlit은 네이티브 앱이 아니라
     앱스토어에 그대로 올릴 수 없기 때문. → 앱스토어를 진지하게 가려면 **프론트 재작성 +
     백엔드 API 분리**라는 큰 공사가 선행되어야 한다.
  3. **데이터 소스(yfinance)와 투자자문 규제**가 결제보다 더 큰 리스크다. §6, §10 필독.

## 1. 제품 비전 & 문제 정의

### 1.1 무엇을 푸는가
개인 투자자가 "이 종목/포트폴리오를 과거에 샀다면 어땠을까?"를 궁금해할 때,
증권사 HTS나 엑셀로는 다음을 쉽게 못 본다:
- 전고점 대비 낙폭이 특정 % 이상일 때 **트리거 재투자**했다면?
- 배당을 **재투자 vs 현금 수령**했을 때 장기 격차는?
- 은퇴 목돈으로 사서 **매월 생활비를 인출(FIRE)**했다면 자산이 버텼을까, 언제 고갈됐을까?
- 마켓별 **원천징수세·통화**까지 반영한 세후 결과는?

이 도구는 티커 선택만으로 위 질문을 즉시 시뮬레이션한다.

### 1.2 왜 지금 (Why now)
- 국내외 **FIRE·배당성장 투자** 관심 지속 확대.
- **콘텐츠 → 제품 퍼널**: 유튜브 배당 백테스트 콘텐츠(배투실 등)와 직접 연결 가능.
  영상에서 "직접 돌려보세요" → 앱 유입 → 구독. 이게 남들에게 없는 **획득 채널**이다.

### 1.3 타깃 페르소나 `[가정 — 인터뷰로 검증 필요]`
| 페르소나 | 니즈 | 지불 의사 |
|---|---|---|
| 국내 배당 투자자 (40~60대) | 세후 배당·재투자 비교, 한국어, 원화 | 중 |
| FIRE 지망 (30~40대) | 은퇴 자금 생존 시뮬, 인출 전략 | 상 |
| 해외 dividend-growth 투자자 | 다종목 포트폴리오, USD, 데이터 정확도 | 상 |
| 콘텐츠 시청자(입문) | 무료로 가볍게 체험 | 무료→낮음 |

## 2. 시장 & 경쟁 분석 `[리서치로 보강 필요]`

3. **콘텐츠 연계 획득 채널** — CAC(고객획득비용)를 크게 낮춤.

## 3. ★핵심 전략 결정: 배포 형태 (앱스토어 vs 웹 SaaS)

사용자는 "국내+해외 둘 다, 네이티브 앱스토어"를 선호했다. 이 조합이 **가장 비싸고
복잡한 경로**라, 정면으로 분석한다.

### 3.1 앱스토어의 현실 (제약)
- **Streamlit은 웹앱이다.** 앱스토어엔 네이티브 앱만 올라간다. 그대로는 불가능.
- **단순 웹뷰 래핑 → 심사 리젝**: Apple App Store Review Guideline **4.2 (Minimum
  Functionality)** — "웹사이트를 그냥 감싼 앱"은 거부된다. 네이티브 가치가 필요.
- **디지털 구독은 IAP 강제 + 수수료**: 앱 안에서 구독을 팔면 Apple/Google **인앱결제**를
  써야 하고 수수료 **~30%(2년 차 구독 15%, Small Business Program 시 15%)**. 앱 안에서
  Stripe/포트원 외부결제로 디지털 구독 유도 → **정책 위반**(리더 앱 등 예외는 매우 제한적).
- **결과**: 앱스토어를 제대로 가려면 (1) **프론트를 네이티브(React Native/Flutter)로 재작성**,
  (2) 파이썬 엔진을 **API 백엔드로 분리**, (3) 결제를 IAP로 이중화 — 큰 공사 + 수수료 손실.

### 3.2 웹 SaaS의 장점
- **결제 자유**: Stripe(해외)·포트원/토스(국내). 수수료 **~3~4%**대.
- **빠르고 저렴한 출시**: 지금 Streamlit 코드를 거의 그대로 유료화 가능.
- **반복 배포**: 심사 없이 즉시 업데이트.

### 3.3 "둘 다 시장"은 결제만 지역 분기
- 웹에서는 **접속 지역/사용자 설정에 따라 결제 PG만 분기**하면 된다:
  - 해외 → **Stripe Billing**
  - 국내 → **포트원(빌링키 정기결제)** 또는 토스페이먼츠
- 앱/데이터/기능은 공용. 즉 "둘 다 시장"은 웹에서 오히려 **쉽다**(앱스토어보다).

### 3.4 권고 결론
| Phase | 형태 | 결제 |
|---|---|---|
| **1 (출시)** | **웹 SaaS** | Stripe(해외) + 포트원(국내) — 지역 분기 |
| 2 (성장) | 웹 SaaS + 모바일 최적화(PWA) | 동일 |
| 3 (검증 후) | 네이티브 앱(재작성) 또는 하이브리드 | 앱=IAP, 웹=기존 결제 |

> **핵심 메시지**: 앱스토어를 최종 목표로 두더라도 **웹 SaaS를 건너뛰지 말 것.**
> 웹으로 시장·전환율·데이터 비용을 먼저 검증한 뒤, 수요가 확인되면 그때 앱에 투자한다.
> "무조건 아이폰 앱부터"는 IAP 30% + 재작성 비용 + 심사 리스크를 초기에 다 떠안는 선택.

## 5. 기술 아키텍처

### 5.1 현행 → 목표
```
[현행] Streamlit 모놀리식 (app.py → dashboard/fire render(), 엔진 global_cup/)
                       │  로그인·결제·DB 없음, 데이터는 yfinance 실시간
                       ▼
[Phase 1 목표] Streamlit + 인증 + DB + 결제 + 데이터 레이어
```

### 5.2 Phase 1 구성요소 (웹 SaaS)
| 축 | 선택 `[가정]` | 이유 |
|---|---|---|
| **인증** | Streamlit `st.login()` (OIDC) + Auth0/Clerk | 비밀번호 자체 관리 회피, 소셜 로그인 |
| **DB** | Supabase(Postgres) | Auth·DB·RLS 통합, 1인 운영 편의 |
| **결제(해외)** | Stripe Billing + Checkout + Webhook | 반복결제·체험·해지·인보이스 표준 |
| **결제(국내)** | 포트원(빌링키) 또는 토스페이먼츠 | 국내 카드·정기결제 |
| **호스팅** | Cloud Run / Render / Fly.io | 웹소켓 유지, 오토스케일, 세션 어피니티 |
| **데이터** | §6 참조 (yfinance→라이선스 전환) | 상용 리스크 |

**엔티틀먼트 흐름**: 로그인 → DB에서 `subscription.status` 조회(세션 캐시) →
`active`면 프로 기능 open, 아니면 업그레이드 유도. Stripe/포트원 **Webhook**이
결제 이벤트를 받아 DB를 갱신(신뢰의 원천은 Webhook, 클라이언트 아님).

### 5.3 DB 스키마 스케치
```
users(id, email, provider, created_at)
subscriptions(user_id, provider['stripe'|'portone'], customer_id,
              plan, status['trialing'|'active'|'past_due'|'canceled'],
              current_period_end, region)
saved_scenarios(id, user_id, payload_json, created_at)
usage_events(user_id, event, ts)   -- 전환 퍼널 분석용
```

### 5.4 앱스토어(Phase 3) 갈 경우의 아키텍처 변화
- 파이썬 엔진(`global_cup/`)을 **FastAPI 백엔드**로 감싸 REST/JSON API화.
- 프론트: **React Native / Flutter** 재작성(또는 Flutter+웹 공용).
- 결제 이중화: 앱=IAP, 웹=Stripe/포트원. 엔티틀먼트는 백엔드에서 통합 관리.
- → **사실상 재구축**. Phase 1의 Streamlit은 웹 채널로 계속 운영 가능.

## 6. ★데이터 소스 & 라이선스 (핵심 리스크)

- **현재 `yfinance`는 야후 파이낸스 스크래핑**이다. 개인/연구용은 무방하나
  **상용 유료 서비스에는 ToS·법적 회색지대**다. 유료화 전 반드시 전환 검토.
- 대체 공급자 `[비용 조사 필요]`:
  | 공급자 | 커버리지 | 대략 비용 |
  |---|---|---|
  | Polygon.io | 미국 주식/옵션 | 월 $29~ |
  | Tiingo | 미국+글로벌, 배당 | 월 $10~ |
  | EOD Historical Data | 글로벌+한국(KRX 포함) | 월 $20~80 |
  | 한국거래소/데이터몰, KIS API | 국내 | 별도 |
- **배당 데이터 정확도**가 이 제품의 생명 — 공급자 선정 시 배당/분할 조정 품질을 최우선 검증.

## 7. 수익화 & 단위 경제성 `[가정]`

- **모델**: 프리미엄(Freemium) → 프로 월/연 구독.
- **개략 단위 경제성**(검증 전 가정):
  - 프로 ARPU ≈ ₩9,900/월, 결제수수료 3.5% 차감.
  - 변동 데이터비/유저 → 라이선스 정액이면 유저당 한계비용 낮음.
  - **콘텐츠 채널 CAC가 낮다**는 게 이 사업의 핵심 레버.
- **손익분기 `[가정]`**: 월 고정비(§9)를 프로 구독자 N명이 커버 → N ≈ 고정비 ÷ (ARPU×마진).

## 10. ★리스크 & 대응

| 리스크 | 심각도 | 대응 |
|---|---|---|
| **투자자문 규제(자본시장법)** — 백테스트가 "이 종목 사라"는 **유사투자자문/투자권유**로 오인 | 높음 | 명확한 **면책 고지**("과거 성과는 미래를 보장하지 않음", "투자 조언 아님, 교육·시뮬레이션 도구"), 특정 종목 추천 표현 배제, 필요시 법률 자문 |
