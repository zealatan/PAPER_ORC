종목만 바꾸면 찍히는 라인.
video_spec.json 하나가 관통한다.

종목마다 단일 진실원(spec) 을 두고 모든 단계가 이걸 읽고 씁니다. 그래야 단계가 분리돼 에이전트가 병렬로 일하고, 부품을 갈아끼울 수 있어요 — 이게 프로토콜입니다. 코카콜라 1편을 만들며 부품 대부분이 이미 완성됐고, 지금은 그걸 “라인”으로 세우는 단계.

02

프로토콜 스키마

단계 간 계약. 이 형태만 지키면 부품 교체·병렬화 자유

video_spec.json모든 단계의 입출력 = 이 객체의 부분집합
video_spec = {
  ticker, 회사명, 테마,                        // 입력 (사람이 지정)
  data:     { 월봉가격[], 배당[],                // ← 단계1: 결정론적 엔진
              사업개요(지역매출·증배연수·배당성향·최근실적·브랜드) },
  backtest: { FIRE시나리오[ {원금, 월인출, 물가반영,   // ← 단계1: 진실의 숫자
                         생존여부, 파산연도, 최종자산} ],
              전략비교{ 목돈, 적립, 폭락매수 } },
  story:    { 훅(A/B 설정), 섹션별_나레이션[], 자막[] }, // ← 단계2 (QA가 backtest와 대조)
  scenes:   [ {tpl, data, bgid, subLines,          // ← 단계3 (= 덱 JSON)
                subTimes, subHold} ],
  assets:   { bg클립[], 썸네일, 제목, 설명, 태그 }   // ← 단계4
}
03

멀티에이전트가 들어갈 자리

Workflow 오케스트레이션 — 결정론 부분은 코드, 창작·검증은 에이전트

종목 배치 팬아웃

  • 종목 리스트 → 각 종목 파이프라인 병렬 실행
  • 한 종목 안: 대본 섹션 · 썸네일안 · 제목/설명 · 차트 캡션 동시 생성

적대적 QA (핵심)

  • “2015년 파산이 backtest와 맞나?”를 독립 검증
  • 데이터는 엔진에서만, 대본은 인용만 — LLM이 숫자 지어내기 차단

품질 심사

  • 훅·대본을 여러 각도로 평가하는 심사 에이전트
  • 가장 강한 버전 채택 + 러너업 아이디어 이식
04

정직한 경계

어디까지 자동이고 어디서 사람이 필요한가

완전 자동 종목명만

데이터 → 백테스트 → 대본 → 덱 → 더빙 → 렌더. 티커 하나 넣으면 마스터 영상까지.

반자동 · 사람손 검수

AI 배경영상 생성(외부 생성기), 최종 크리에이티브 검수. 목소리는 클론으로 자동.

1순위 리스크 정확성

금융 콘텐츠 = 숫자가 생명. 데이터는 엔진 · 대본은 인용 · QA는 대조 구조가 방어선.

05

구축 로드맵

뼈대부터 세우고 멀티에이전트를 얹는다

1
재현화 — 코카콜라를 spec 하나에서 다시 찍히게
지금 흩어진 하드코딩을 video_spec.json으로 수렴. “같은 결과를 spec에서 재생성” 확인.
out · spec 스키마 확정 + 코카콜라 spec 1건
2
파라미터화 — 덱=템플릿, 백테스트=run(ticker, scenarios)
덱 HTML을 플레이스홀더 템플릿으로, 엔진을 임의 종목 입력 함수로.
out · pipeline/ 스켈레톤 (엔진→spec→덱)
3
멀티에이전트 얹기 — 대본 · QA · 포스트를 Workflow로
섹션 팬아웃 생성 + 적대적 QA 게이트 + 심사. 결정론 단계는 코드로 유지.
out · 대본 자동생성 + 정확성 게이트
4
테스트 종목 — 배당귀족 1편 엔드투엔드
펩시코 · 맥도날드 · P&G 중 하나로 티커만 넣어 완편 검증.
out · 재현 가능한 1편 + 러닝 체크리스트
